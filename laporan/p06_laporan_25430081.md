2. Ringkasan Dasar Teori
DML (`Data Manipulation Language`) adalah kelompok perintah SQL yang berfungsi untuk memanipulasi data di dalam objek basis data yang telah didefinisikan sebelumnya oleh DDL. Perintah utama DML meliputi pencatatan data baru (`INSERT`), pembaruan data (`UPDATE`), dan penghapusan data (`DELETE`). 

Pada lingkungan produksi dan laboratorium, pengisian data serta pembaruan data harus memperhatikan aspek-aspek integritas data berikut:
- **Integritas Referensial (`FOREIGN KEY`)**: Memastikan data transaksi (anak) selalu merujuk pada entitas induk yang valid di tabel master.
- **Batasan Domain & Keunikan (`CHECK` & `UNIQUE`)**: Mencegah masuknya nilai di luar jangkauan logika bisnis (seperti nilai angka di luar range 0-100 atau SKS negatif) serta mencegah duplikasi identitas master (seperti NPM/NIM dan NIP).
- **Mode Aman Update (`sql_safe_updates`)**: Kebijakan laboratorium yang membatasi operasi `UPDATE` dan `DELETE` tanpa klausa `WHERE` yang melibatkan kolom kunci (`Primary Key` / `Unique Key`) guna mencegah kerusakan data secara tidak sengaja.

 4. Jawaban Titik Analisis
- Titik Analisis 1: Mengapa eksekusi `UPDATE mata_kuliah SET sks_mk = sks_mk + 1;` menghasilkan `ERROR 1175 (HY000)`?  
  `Jawab:` Karena sesi MariaDB berada dalam `Safe Update Mode` (`sql_safe_updates = 1`). Server secara otomatis menolak operasi `UPDATE` atau `DELETE` yang tidak menyertakan klausa `WHERE` pada kolom kunci (`Key Column`) guna mencegah perubahan data secara tidak sengaja pada seluruh baris tabel.
- Titik Analisis 2: Bagaimana perintah `INSERT INTO ... SELECT` membantu menjaga konsistensi referensial pada pengisian `detail_krs`?  
  `Jawab:` Perintah `INSERT INTO ... SELECT` mengambil kunci primer (`id_krs` dan `id_kelas`) secara langsung dari tabel induk (`krs` dan `kelas`) yang sudah terbukti valid, sehingga menghilangkan risiko kesalahan ketik (`human error`) nilai kunci asing (`foreign key`) dan menjamin tidak ada entri fiktif (`orphan record`).
- Titik Analisis 3: Mengapa eksekusi `DELETE FROM mahasiswa WHERE id_mhs = 1;` ditolak oleh server dengan `ERROR 1451`?  
  `Jawab:` Karena `id_mhs = 1` telah digunakan sebagai rujukan kunci asing (`foreign key`) pada tabel anak `krs`. Untuk menjaga integritas referensial data perkuliahan, MariaDB menolak penghapusan data induk yang masih memiliki transaksi aktif terkait.

- Pengujian Skenario Safe Update: Berhasil membuktikan bahwa perintah `UPDATE mata_kuliah SET sks_mk = sks_mk + 1 WHERE id_mk = 1;` berjalan sukses (`Query OK, 1 row affected`) setelah ditambahkan klausa `WHERE` pada kolom `Primary Key`, membedakannya dengan eksekusi tanpa `WHERE` yang ditolak oleh `Safe Update Mode`.
