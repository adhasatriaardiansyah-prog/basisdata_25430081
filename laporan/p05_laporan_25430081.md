 1. Tujuan Praktikum
- Menerjemahkan skema relasional 3NF sistem Koperasi Mahasiswa (Kopma) menjadi perintah `CREATE TABLE` dengan tipe data yang tepat dan efisien di MariaDB.
- Menerapkan constraint secara komprehensif (`PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `NOT NULL`, `DEFAULT`, `CHECK`, dan `ON DELETE CASCADE/SET NULL`) untuk menjaga integritas data.
- Mengubah (`ALTER TABLE`) dan menghapus (`DROP TABLE`) struktur tabel dengan memperhatikan ketergantungan referensial antar tabel.
- Membuktikan respons server MariaDB dalam menolak data yang melanggar aturan integritas constraint melalui penangkapan kode galat (`error code`).

 2. Ringkasan Dasar Teori
DDL (`Data Definition Language`) adalah kelompok perintah SQL yang berfungsi untuk mendefinisikan struktur basis data, meliputi pembuatan (`CREATE`), pengubahan (`ALTER`), dan penghapusan (`DROP`) objek basis data. Penggunaan `Constraint` sangat penting untuk menegakkan aturan bisnis secara otomatis langsung pada tingkat mesin penyimpanan (InnoDB), mencakup:
- `PRIMARY KEY` & `UNIQUE`: Menjamin keunikan baris dan mencegah duplikasi data master maupun transaksional.
- `FOREIGN KEY`: Menjaga integritas referensial antar tabel anak dan tabel induk, didukung opsi penghapusan `ON DELETE CASCADE` atau `ON DELETE SET NULL`.
- `CHECK`: Membatasi domain nilai atribut agar sesuai dengan logika bisnis operasional (misal stok dan harga tidak boleh bernilai negatif).

 4. Jawaban Titik Analisis
- Titik Analisis 1: Mengapa pengujian `Foreign Key` pada tabel `penjualan` dengan `id_petugas = 99` menghasilkan `ERROR 1452`?  
  `Jawab:` Karena kolom `id_petugas` pada tabel `penjualan` bertindak sebagai kunci tamu yang merujuk ke tabel induk `petugas`. Ketika nilai `99` tidak ditemukan di tabel `petugas`, server MariaDB menolak operasi untuk mencegah terjadinya data transaksi fiktif (`orphan record`).
- Titik Analisis 2: Bagaimana mekanisme penegakan `Check Constraint` mencegah kesalahan operasional stok?  
  `Jawab:` Melalui penerapan `CONSTRAINT ck_barang_stok CHECK (stok_barang >= 0)`, server secara otomatis menolak perintah `UPDATE` atau `INSERT` yang mencoba memasukkan nilai stok negatif (`ERROR 4025`), sehingga akurasi inventaris Kopma selalu terjaga.
- Titik Analisis 3: Mengapa urutan penghapusan tabel (`DROP TABLE`) harus dimulai dari tabel anak ke tabel induk?  
  `Jawab:` Karena tabel anak memiliki ketergantungan (`foreign key`) terhadap tabel induk. Jika tabel induk dihapus terlebih dahulu, integritas relasi akan rusak dan server akan menolak perintah tersebut. Oleh karena itu, urutan `DROP TABLE` dimulai dari tabel transaksi detail (`detail_pembelian`, `detail_penjualan`), tabel transaksi header (`pembelian`, `penjualan`), hingga tabel master (`petugas`, `anggota`, `barang`, `pemasok`).
